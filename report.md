### Описание сервисной части
**Демонстрация работы сервиса доступна по [ссылке](https://disk.yandex.ru/i/QgJbH0ONL7pltQ)**

В **FastAPI** сервисе есть одна главная ручка - /get_vids. Она
1. Получает на вход тексты и кодирует их моделью, которую можно выбрать в config.py (но у нас пока только одна модель)
2. Ищет с помощью gensim-а в корпусе видео самые близкие кусочки видео по эмбеддингам
   
Корпус должен находиться на Яндекс Диске и иметь такие файлы:
- .pt файл с эмбеддингами
- .mp4 файлы с полными видео корпуса, где названия совпадают с полями "video" в .json файле

Также для EDA и работы сервиса понадобится файл .json с мета информацией. В нём должен храниться список словарей (каждый словарь - кусочек видео) той же длины, что и количество эмбеддингов в .pt файле. Требуются следующие поля:
- "text" - текст субтитров
- "start" - конец кусочка видео
- "end" - начало кусочка видео
- "video" - название видео

Пример файла можно найти [тут](https://github.com/AlinaRechina/SL_retrieval/blob/fastapi_service/data/test.json) (и его же можно вставить в сервис при тестировании).

В **streamlit** части запрашиваются токен АПИ Яндекса, путь к папке с файлами на диске, файл .json с мета-информацией и запрос.

Там также считается EDA по субтитрам предоставленного датасета (подгружаемого файла .json, описанного выше) по аналогии с [EDA, сделанным для 2-ого чекпоинта](https://github.com/AlinaRechina/SL_retrieval/blob/fastapi_service/notebooks/EDA/EDA%20Captions.ipynb).

### Как всё запустить
1. Сбилдить Докер в корневой папке проекта
2. Найти приложение на http://localhost:8501
   
________________________________________________________________________________________________________________
Особенности работы с файлами локально:
- .pt файл с эмбеддингами скачивается целиком (весит менее 1Гб)
- Видео скачиваются только нужные, но целиком
Для работы сервиса требуется загрузить нужные файлы на диск и ввести Yandex Disk API token в приложение.
